# MATLAB / Simulink toolbox

The MATLAB side of State-Space Studio: the same five plants, the same designs and the same test profiles as the Python package, written for the Control System Toolbox. The original lab scripts were refactored into shared plant models and helper functions (instead of copy-pasted blocks per task), closed loops are simulated with `lsim` on their augmented state-space models, and the Simulink diagrams are generated by a script rather than stored as binaries.

## Run it

**Verification status:** the Python implementation is tested locally; these MATLAB scripts and the Simulink builder have not been executed in MATLAB here. The cross-check script reports deviations but is not a certified validation gate. Generated model files may acquire local user metadata when saved by MATLAB and are excluded from the upload folder.

```matlab
cd matlab
results = run_all();             % three studies; prints the analyses, opens the figures
results = run_all("figures");    % same, and exports every figure to matlab/figures/*.png
```

Requirements: MATLAB R2020a or newer, Control System Toolbox. `run_all` adds `models/`, `toolbox/` and `studies/` to the path.

### Simulink (optional)

```matlab
cd simulink
build_simulink_models();            % writes three .slx files to matlab/simulink/build/
report = run_simulink_crosscheck(); % simulates them and compares with lsim
```

| Model | Structure | Used for |
| --- | --- | --- |
| `sc_drivetrain_state_feedback` | plant from integrator and gain blocks, `u = V w - K x`, constant `w` and load torques `z` | drivetrain pole placement |
| `sc_three_tank_state_feedback` | same structure with step blocks for the reference and the leak | three-tank pole placement and LQR |
| `sc_three_tank_pi` | integrator on `e = w - y`, `u = Kp e + Ki xi - Kpi x` | three-tank PI state feedback |

Every block parameter is a workspace variable (`A`, `B`, `C`, `D`, `E`, `K`, `V`, `Kp`, `Ki`, `Kpi`, `x0`, ...), so one diagram serves several designs; `run_simulink_crosscheck` supplies them through `Simulink.SimulationInput`. The plant is assembled from integrators and gain blocks rather than a State-Space block, which keeps every signal visible. Generated models are ignored by git (`matlab/simulink/build/`).

## Layout

```text
matlab/
├── run_all.m                       entry point
├── models/                         plant models -> struct with A, B, C, D, E, states, ...
│   ├── rc_ladder_model.m
│   ├── coupled_mimo_model.m
│   ├── mass_spring_damper_model.m
│   ├── drivetrain_model.m          assembled from inertia, damping and stiffness matrices
│   └── three_tank_model.m
├── toolbox/                        analysis, design, closed loops, plotting
│   ├── structural_analysis.m       poles, stability class, Kalman ranks
│   ├── second_order_poles.m        dominant poles from a settling-time target
│   ├── prefilter_gain.m            V for zero steady-state error
│   ├── pi_state_feedback_design.m  augmented pole placement -> Kp, Ki, Kpi
│   ├── state_feedback_loop.m       u = V w - K x  (inputs [w; z], outputs [y; u])
│   ├── pi_state_feedback_loop.m    u = Kp e + Ki xi - Kpi x
│   ├── step_signal.m, plot_states.m, plot_poles.m, export_figure.m, ...
├── studies/
│   ├── study_01_fundamentals.m     RC ladder, coupled system, mass-spring-damper
│   ├── study_02_drivetrain.m       analysis, open loop, pole placement, five test cases
│   └── study_03_three_tank.m       analysis, open loop, four controllers on one profile
└── simulink/
    ├── build_simulink_models.m
    └── run_simulink_crosscheck.m
```

## Python ↔ MATLAB

| Python (`state_space_studio`) | MATLAB |
| --- | --- |
| `plants.drivetrain()` | `drivetrain_model()` |
| `plants.three_tank()` | `three_tank_model()` |
| `analysis.structural_report(A, B, C)` | `structural_analysis(plant)` |
| `design.second_order_poles(200, 1)` | `second_order_poles(200, 1)` |
| `design.ackermann(A, B, poles)` | `acker(A, B, poles)` |
| `design.prefilter(A, B, C, K)` | `prefilter_gain(A, B, C, K)` |
| `design.pi_state_feedback(A, B, C, poles)` | `pi_state_feedback_design(A, B, C, poles)` |
| `design.lqr(A, B, Q, R)` | `lqr(A, B, Q, R)` |
| `loops.state_feedback_loop(plant, K, V)` | `state_feedback_loop(plant, K, V)` |
| `loops.pi_state_feedback_loop(plant, gains)` | `pi_state_feedback_loop(plant, gains)` |
| `LTISystem.simulate(t, u, x0)` | `lsim(sys, u, t, x0)` |
| `analysis.step_metrics(...)` | `stepinfo(...)` |
| `scenarios.drivetrain_study()` | `study_02_drivetrain()` |

Both implementations use identical parameters, pole locations, weights and test profiles, so the gains (for example `V = 1.0667` for the drivetrain) and the result tables correspond to [docs/results.md](../docs/results.md); settling times from `stepinfo` can differ in the last digit because of its interpolation.
